Course · Lesson 0006

Bitmasks

A subset is an integer. Once you see that, the budget table's O(2n·n) stops being notation and becomes two nested loops you can count.

The dot-n you have never explained

The budget table row you used last lesson says O(2n·n), not O(2n). You have read past that ·n five times now, the same way you read past log n before lesson 0003.

It is there because enumerating subsets is genuinely two loops: one over the 2n subsets, and one over the n elements to work out which are in it. This lesson gives you the representation that makes both loops obvious, and the counting falls out for free.

A subset is an integer

From the Competitive Programmer's Handbook: “Every subset of a set {0, 1, 2, …, n−1} can be represented as an n bit integer whose one bits indicate which elements belong to the subset. This is an efficient way to represent sets, because every element requires only one bit of memory, and set operations can be implemented as bit operations.”1

Concretely, with n = 5 items:

IntegerBinaryMeans the subset
000000{ }   nothing chosen
100001{0}   item 0 only
500101{0, 2}
3111111{0, 1, 2, 3, 4}   everything

Read bits right to left, bit i meaning “is item i in?”. The integers 0 through 2n−1 are then exactly the subsets, each one once. Which gives you the loop:

for mask in range(1 << n): Counting from 0 to 2n−1 enumerates every subset, in order, with no bookkeeping.

1 << n is 2n. That is the whole trick, and it is why bitmask code is short.

The operators

Six of them, and you need all six.2

OpDoesExampleUse it for
a & bAND: 1 where both are 10101 & 0011 = 0001Testing a bit; intersection
a | bOR: 1 where either is 10101 | 0011 = 0111Setting a bit; union
a ^ bXOR: 1 where they differ0101 ^ 0011 = 0110Flipping a bit; pairing off
a << kShift left, “multiplication by pow(2, k)”1 << 3 = 1000Building bit k
a >> kShift right, “floor division by pow(2, k)”1100 >> 2 = 0011Moving bit k to the end
~aInvert every bit~5 = −6Careful. See below.

The three idioms you will type a hundred times, for item i:

mask |  (1 << i)      # add item i to the set
mask &  ~(1 << i)     # remove item i from the set
mask >> i & 1         # is item i in the set?  → 0 or 1

That last line needs no brackets: >> binds tighter than &, so it reads as (mask >> i) & 1. And unlike in C, a following == 1 is also safe in Python, because & binds tighter than ==.2

Set operations, and the one that does not survive Python

CPH gives the translation table between set notation and bit operations:1

Set operationBit syntaxWorks in Python?
intersectiona & bYes
uniona | bYes
differencea & ~bYes
complement~aNo. Use full ^ a.

The one place the C++ advice breaks. That table assumes a fixed-width integer, where inverting 32 bits gives you the complement. Python's “integers have unlimited precision”,2 so there is no width to invert within: ~0b0101 is −6, not 0b1010. To complement within n bits, XOR against an all-ones mask: 

full = (1 << n) - 1     # n ones: for n=4, 0b1111
complement = full ^ a   # for a=0b0101 → 0b1010 ✓
Note a & ~b for difference is still fine, because the AND masks the runaway sign bits away.

Counting the loop: where the dot-n comes from

Here is subset enumeration in full:

for mask in range(1 << n):              # 2^n masks
    chosen = [a[i] for i in range(n)    #   × n bits to test
              if mask >> i & 1]
    ...

Now apply the counting rule from lesson 0002: nesting multiplies. The outer loop runs 2n times, the inner comprehension runs n times per mask, and neither has a counter that survives across iterations (so lesson 0004's amortised escape does not apply here). They multiply.

2n masks × n bits each = O(2n·n) The budget table said so all along. Now you can derive it.

At n = 20 that is 106 × 20 = 2·107. Against a C++ budget, fine. Against Python's ~107/second, it is right at the edge, which is the honest reason this lesson exists: at these sizes the ·n is not a rounding error, it is the difference between passing and not.

Popcount: dropping the inner loop when you only need the size

If all you want is how many items are in the subset, you do not need the inner loop at all:2

mask.bit_count()        # Python 3.10+, runs in C
bin(mask).count("1")    # works everywhere; use if the judge is older

“Return the number of ones in the binary representation of the absolute value of the integer. This is also known as the population count.”2 Check your judge's Python version before relying on bit_count; it arrived in 3.10 and some judges lag.

The payoff: Apple Division, rewritten

Lesson 0005 solved CSES 1623 with nested combinations calls. Here it is as a bitmask:

n = int(input())
a = list(map(int, input().split()))
total = sum(a)

best = total
for mask in range(1 << n):
    first = sum(a[i] for i in range(n) if mask >> i & 1)
    best = min(best, abs(total - 2 * first))
print(best)

Shorter, one loop instead of two, and no itertools import. Both versions are O(2n·n) and both are correct; the bitmask version is the one you can write from memory at minute 40 of a contest.

Two honest notes. First, this enumerates each split twice (mask and its complement give the same partition), so you can halve the work by looping to 1 << (n - 1). A factor of two never changes a complexity class, but at the edge of the Python budget it is free and worth taking. Second, itertools generates in C while a bitmask loop is interpreted Python, so for the same algorithm combinations can actually be quicker despite the uglier code. Lesson 0004's warning applies again: the asymptotically identical solution is not always the faster submission.

Two bit tricks worth knowing

Not for their own sake. These two show up constantly:

x & (x - 1)     # clear the lowest set bit:  0b101100 → 0b101000
x & -x          # isolate the lowest set bit: 0b101100 → 0b000100

The first gives you a loop that runs once per set bit rather than once per bit position, which turns an n into a popcount. The second is the engine inside a Fenwick tree, which is well beyond this mission but you will meet the idiom again.

One property worth filing away, from USACO Guide: “xor is its own inverse, i.e. x⊕x = 0”.3 That single fact is the entire solution to a surprising number of problems where everything appears twice except one thing.
