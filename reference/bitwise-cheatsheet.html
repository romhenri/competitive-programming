Bitwise & Bitmask Cheat Sheet

Python syntax for treating an integer as a set. Everything here is verified against CPython; the C++ advice that does not port is marked.

Operators

OpMeaningExample

a | bOR: 1 where either is 10b0101 | 0b0011 = 0b0111

~aInvert all bits = −a−1~5 = −6  (see trap)

Precedence (tightest first): ~, then << >>, then &, then ^, then |, then comparisons.2 Consequences worth knowing:

  • mask >> i & 1 means (mask >> i) & 1. Correct as written.
  • mask & 1 == 1 means (mask & 1) == 1. Safe in Python, unlike C where it is a classic bug.
  • a & b | c means (a & b) | c. Bracket anyway for the reader.

Single-bit idioms

mask |  (1 << i)      # add item i
mask &  ~(1 << i)     # remove item i
mask ^  (1 << i)      # toggle item i
mask >> i & 1         # test item i  → 0 or 1
mask &  (1 << i)      # test item i  → 0 or nonzero

Whole-set idioms

0                     # empty set
(1 << n) - 1          # full set: n ones
1 << n                # 2^n, the number of subsets

a & b                 # intersection
a | b                 # union
a & ~b                # difference (a minus b)  — safe, the AND clips
full ^ a              # complement — NOT ~a, see below
a & b == a            # a is a subset of b

mask.bit_count()      # size of the set (Python 3.10+)
bin(mask).count("1")  # size of the set (any version)
mask.bit_length()     # index of highest set bit, + 1

The trap: ~a is not a complement in Python. The CPH table lists ~a for set complement, but that assumes a fixed-width C++ int. Python's “integers have unlimited precision”,2 so there is no width to invert within and ~0b0101 is −6, not 0b1010. Always complement with full ^ a where full = (1 << n) - 1. Difference via a & ~b stays fine, because the AND discards the runaway high bits.

Enumeration templates

All 2n subsets

for mask in range(1 << n):
    chosen = [a[i] for i in range(n) if mask >> i & 1]
    ...

O(2n·n): 2n masks times n bit tests. Drop to O(2n) when you only need the size, by using bit_count() instead of the inner loop.

Subsets of exactly k elements

for mask in range(1 << n):
    if mask.bit_count() == k:
        ...

Still O(2n) because you filter after generating. If k is small, itertools.combinations(range(n), k) generates only the C(n,k) you want, in C.

Every subset of a given mask

sub = mask
while sub:
    ...              # process sub
    sub = (sub - 1) & mask
# the empty subset is not visited by the loop; handle it separately

Over all masks this totals O(3n), not O(4n). Needed for bitmask DP; beyond the current mission, but this is the idiom you will look up.

Bit tricks

x & (x - 1)Clears the lowest set bitLooping once per set bit

x and x & (x - 1) == 0True if x is a power of twoChecking single-element sets. The leading x is required: without it, 0 reports as a power of two.
x ^ (x >> 1)Gray code of xSequences differing by one bit
x & 1Parity of xOdd/even without %

XOR is its own inverse: x ^ x = 0 and x ^ 0 = x.3 So XOR-ing a whole list cancels every value that appears twice and leaves the one that appears once. It is also associative and commutative, so order never matters.

Python notes for the judge

  • int.bit_count() arrived in Python 3.10.2 On an older judge use bin(x).count("1"), which is also C-speed.
  • Integers are arbitrary precision, so shifts never overflow. A 1 << 10000 is legal and slow, not wrong.
  • Negative shift counts raise ValueError.2
  • A bitmask loop is interpreted. itertools generates in C. For the same algorithm, combinations can beat a hand-written mask loop on the clock even though both are O(2n·n).

Before you submit

  1. Did you use ~a where you meant full ^ a?
  2. Is n the number of items, so the loop bound is 1 << n and not n?
  3. Does the empty mask (0) need handling, and is it a valid answer?
  4. Are you enumerating each partition twice by symmetry? Halve the range if so.
  5. Substitute and count: 2n × body. (budget table)
