The Complexity Budget Table

Read n from the constraints. Look up what you're allowed to spend. Then choose your algorithm.

≈ 108 simple operations per second The judge's budget. Time limits are usually 1–2 s, so ~108–2·108 operations total.

The table

Find the largest n in the problem's constraints, then read across. Anything at or above your row is safe; anything below it is a TLE.

Source: USACO Guide — Time Complexity. Their exact wording on the machine: “a conservative estimate for the number of operations the grading server can handle per second is 108, but it could be closer to 5·108 given good constant factors.”

The two landmarks worth memorising

If you remember nothing else from the table, remember these two rows. They cover the majority of contest problems:

Constraint you'll seeWhat it is telling you
n ≤ 1000“O(n2) is intended.” A double loop is expected — stop looking for something clever.
n ≤ 2·105“O(n log n) is intended.” Almost always: sort it, or use a set/heap. O(n2) will TLE.

The Python tax

The table above assumes C++. Python executes roughly 10–50× fewer operations per second, because every operation goes through the interpreter. Practical adjustments:

  • Treat your real budget as closer to 107 Python-level operations per second, not 108.
  • Work pushed into C — sorted(), sum(), set lookups, slicing, str.join — runs at close to C++ speed. A Python loop does not. Prefer the built-in over the loop, always.
  • When the table says your complexity is borderline, in Python assume it fails.
  • If the judge offers PyPy, use it — it closes much of the gap.

Caveat: the 10–50× figure is folklore from community blogs, not a measurement. This workspace has a note to measure it properly — see Gaps in RESOURCES.md.

Sanity checks before you submit

  1. What is the biggest n in the constraints?
  2. What is my solution's complexity?
  3. Substitute: how many operations is that, actually? (n = 2·105, O(n2) → 4·1010. Dead.)
  4. Is there a second variable? Many problems have n queries and q queries — the cost is often q · (cost per query).
  5. Is there a sum-of-n clause? “the sum of n over all test cases does not exceed 2·105” means you budget against the sum, not per test case.
