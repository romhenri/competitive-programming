Python Operation Costs

What every line actually costs. The accidental O(n²) you wrote is almost certainly on this page.

A loop is O(n) × the cost of its body In Python the body is frequently not O(1). That is the whole problem.

Figures below are from the official Python Wiki — TimeComplexity, which documents CPython's actual implementation. n is the size of the container; k is the size of the argument or slice.

list

Internally an array. The expensive operations are the ones that touch the front, because everything after it must shift.1

OperationCostIn a contest
a[i], a[i] = xO(1)Free. Index all you like.
len(a)O(1)Free — the length is stored.
a.append(x)O(1)Free. Amortised — see below.
a.pop()O(1)Free. Popping the end only.
a.pop(0)O(n)Trap. Use deque for a queue.
a.insert(i, x)O(n)Trap. Shifts the tail every call.
del a[i]O(n)Trap. Same shifting cost.
x in aO(n)The classic trap. Use a set.
a.count(x), a.index(x)O(n)Full scan, every call.
min(a), max(a), sum(a)O(n)Fine once. Fatal inside a loop.
a[i:j]O(k)Copies. Slicing is never a view.
a.sort(), sorted(a)O(n log n)Cheap, and the fastest thing you own.
a.copy(), list(a)O(n)Watch for this hiding in a loop.
[0] * nO(n)The right way to preallocate.

set  — and frozenset

Hash-based. The single most valuable container in competitive Python: it turns O(n) membership into O(1).

OperationCostIn a contest
x in sO(1)The reason sets exist. Worst case O(n), never seen in practice.
s.add(x), s.discard(x)O(1)Free.
s | t (union)O(len s + len t)Builds a new set. Not free.
s & t (intersection)O(min(s, t))Cheaper than union — it scans the smaller.
s - t (difference)O(len s)Proportional to the left side.
s ^ t (symmetric)O(len s)—

Sets are unordered. There is no “smallest element of a set” in O(1) — min(s) is O(n). If you need the minimum repeatedly, you want a heap, not a set.

dict

Same hash table as set, with values attached. Since Python 3.7 it preserves insertion order, free of charge.

OperationCostIn a contest
k in d, d[k], d[k] = vO(1)Free. Your default lookup structure.
del d[k]O(1)Free.
for k in dO(n)Expected.
d.copy()O(n)Trap when nested in a loop.

Two standard-library shortcuts that save real contest time:

from collections import defaultdict, Counter

adj = defaultdict(list)          # no key-exists check needed
adj[u].append(v)

freq = Counter(a)                # O(n) frequency table, one line
freq.most_common(3)              # top-3, already sorted

collections.deque

A doubly-linked list of blocks. Use it whenever you need a queue — which in practice means every BFS you will ever write.2

OperationCostvs. list
q.append(x), q.pop()O(1)Same as list.
q.appendleft(x), q.popleft()O(1)O(n) on a list. This is the whole point.
q[i] in the middleO(n)Worse than list. Don't index a deque.
q.rotate(k)O(k)No list equivalent.
 
from collections import deque
q = deque([start])
while q:
    node = q.popleft()      # O(1) — with a list this is O(n), so BFS becomes O(n²)

str

Strings are immutable, and that changes the arithmetic completely.

OperationCostIn a contest
s[i], len(s)O(1)Free.
s[i:j]O(k)Copies, like list slicing.
s += c in a loopO(n²)Trap. Rebuilds the whole string each time.
"".join(parts)O(n)The fix. Collect in a list, join once.
sub in sO(n·k)Fine for one check; not inside a loop.
 
# Wrong — O(n²)
out = ""
for x in results: out += str(x) + "\n"

# Right — O(n)
print("\n".join(map(str, results)))

heapq & bisect

Two stdlib modules that buy you a whole complexity class. Both are written in C.

OperationCostUse it for
heapq.heappush(h, x)O(log n)Repeatedly taking the smallest item: Dijkstra, scheduling, top-k.
heapq.heappop(h)O(log n)
heapq.heapify(a)O(n)Cheaper than n pushes. Always heapify a list you already have.
h[0] (peek)O(1)Look without popping.
bisect.bisect_left(a, x)O(log n)Binary search on a sorted list. See Technique by Budget.
bisect.insort(a, x)O(n)Trap. The search is O(log n) but the insert still shifts.

Python has no max-heap. Push -x and negate on the way out. It is the standard trick, not a hack.

A word on “amortised”

a.append(x) is listed as O(1), but occasionally the list is full and CPython must allocate a bigger array and copy everything — an O(n) step. It is still called O(1) because those expensive steps are rare enough that n appends cost O(n) in total. The cost is spread — amortised — across all the calls.

What this means for you: budget against the total, not the worst single call. A loop doing n appends is O(n), full stop. The same reasoning is what makes a two-pointer loop O(n) despite its nested while.

The general rule. Work pushed into a C built-in — sorted, sum, join, set operations — runs at near-C++ speed. The same work written as a Python for loop runs 10–50× slower. When two solutions have the same complexity, pick the one with fewer Python-level iterations. See the Python tax.
