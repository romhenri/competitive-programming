Binary search — the one template

Answers: what is the smallest x in [lo, hi] for which check(x) is true? Learn this shape only; bend the problem to fit it.

lo, hi = LOW, HIGH         # hi must be a value you KNOW passes
while lo < hi:
    mid = (lo + hi) // 2   # floors → mid < hi → always makes progress
    if check(mid):
        hi = mid           # mid works, but keep it as a candidate
    else:
        lo = mid + 1       # mid fails, and so does everything below
answer = lo

For the largest x where check(x) is true, do not invent a second template — search for the smallest x where check(x) is false, and subtract one.

Preconditions — check these or it silently returns nonsense

  1. Monotonic. Once check flips false→true it must stay true. “Binary search on the answer only works if the answer function is monotonic.”1
  2. hi is known-good. The template never tests hi itself. If no answer exists in range, it returns hi and lies to you.
  3. Sorted, if you are searching an array rather than an answer range.

bisect — use it whenever the array is the thing being searched

Runs in C, so it dodges the Python tax. Sort first.2

from bisect import bisect_left, bisect_right

i = bisect_left(a, x)      # first index with a[i] >= x
j = bisect_right(a, x)     # first index with a[j] >  x

x in a          → i < len(a) and a[i] == x
count of x      → j - i
values < x      → i
values <= x     → j
predecessor     → a[i-1] if i > 0 else None      # largest value < x
successor       → a[j]   if j < len(a) else None # smallest value > x

Never insort in a loop. “The insort() functions are O(n) because the logarithmic search step is dominated by the linear time insertion step.”2 n calls to insort is O(n²). If you need a sorted structure with fast inserts, you need a different structure — or a way to sort once up front.

Two pointers — the two shapes

Opposite ends (array must be sorted)

lo, hi = 0, n - 1
while lo < hi:
    s = a[lo] + a[hi]
    if s == target:
        break
    elif s < target:
        lo += 1            # need bigger; a[lo] is eliminated forever
    else:
        hi -= 1            # need smaller

O(n) after an O(n log n) sort. Use for: pairs summing to a target, closest pair, counting pairs under a limit, matching largest with smallest.

Sliding window (same direction)

left = 0
cur  = 0
for right in range(n):
    cur += a[right]        # grow right
    while BAD(cur):
        cur -= a[left]     # shrink left until valid again
        left += 1
    # window a[left..right] is now valid — record it

O(n) total. Use for: contiguous subarrays, longest run satisfying a property, smallest window covering something.

Requires that shrinking helps. Removing a[left] must move cur back towards valid. With all-positive values, sums do this. With negative values a sum window breaks — reach for prefix sums plus a dictionary instead.

Counting a two-pointer loop

A while inside a for is not automatically O(n²). Ask the right question:

How many times in total, across the whole run? Not “how many per outer iteration?” — that question has no answer here.
Inner loop's counter…LoopsResult
never resets, only moves forwardaddO(n + n) = O(n)
resets at the top of each outer passmultiplyO(n²)

This is amortised analysis.3 The code for the two cases looks nearly identical — one line's difference between passing and TLE.

The Python tax on these two

  • bisect, sorted(): run in C. Effectively free. Always prefer them.
  • Hand-written binary search: only ~20–60 interpreted iterations. Free too — unless the check inside it is an O(n) Python loop, in which case price it as n × log C interpreted operations and compare against ~107/second.
  • Two pointers: a pure Python loop, ~2n interpreted steps, no C escape hatch. Fine at 2·105; think twice at 107.
  • Counter-intuitive consequence: an O(n log n) solution that lives inside sorted() can beat a hand-rolled O(n) loop on the clock. Complexity decides who survives a bigger n; it does not always decide today's submission.

Before you submit

  1. Binary search: is check monotonic, and is hi genuinely known-good?
  2. Binary search: does lo advance by mid + 1?
  3. Two pointers: is the array sorted, if the shape needs it?
  4. Sliding window: are all values positive, or have you handled the case where they are not?
  5. Both: substitute the largest n and count. (budget table)
